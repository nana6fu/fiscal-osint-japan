## 何を作ったか
- 右下常駐の🔍ボタン、押すと開く／×で閉じる。全タブで使える（position:fixed, z-index 9998/9999）
- 企業名を入力 → `MINISTRIES_2023/2024/2025` の houjin[] + `STAGE2_DATA.companies` を横断集計
- 会社ごとに分けて、省庁別内訳・件数・JVフラグを表示
- 検索結果見出しに「📅 R5〜R7（2023〜2025年度）の合算値」を明記

## 核心の設計思想
**数字はJS集計（AI不使用）= 事故ゼロ。AIには数字を触らせない。**
- 金額の正確性はJSが保証。Groqに数字計算をさせない＝ハルシネーション構造的に排除
- サイトの既存ポリシー「📄一次資料と🤖AI分析を分ける」と完全一致

## 中立性の担保
- JV（共同企業体）は明示。「A＋B」「含むBJV」等は別カウントし、JVバッジ表示
- **名寄せ（表記統一）はしない**。元データの表記のまま分けて表示
  - 理由：「日本電気＋NECキャピタル」を「日本電気」に寄せると受注額の歪曲になりうる。寄せる＝解釈が入る＝中立サイトが避けるべき恣意性
- 注記3点：単純合計／JVの性質／名寄せなし／年度合算

## 安全設計（レイヤー）
- レイヤー1（JS即弾き）：BLOCK_WORDS で個人情報・暴力・インジェクション系を検出 → AIに到達する前に定型文
- 対象外検索（収録外企業）：「見つからない＋収録範囲案内」で突き放さない
- 入力長制限 maxlength=40

## 経緯（なぜこの形になったか）
1. 出発点：齋藤さん「AI分析がギミック止まり。無料で使えるなら有意義に使いたい」
2. AI分析の棚卸し：カード単位の再要約は「サイトに既にある情報の言い換え」＝ギミック
3. 「有意義」の条件＝静的データに無い価値を生むこと → ①横断集計 ②次の一手 に絞る
4. 当初：随契分析タブ内に手入力フォーム → 「タブに埋もれる」「二重で迷う」課題
5. 齋藤さん発案：右下チャットボット型（全ページから呼べる、畳める）に進化
6. コンソールで集計エンジンを先に検証 → 名寄せ問題・JV表記ゆれ・年度合算の不明示を実装前に発見・対処

## 検証で見つけた論点（実装前にコンソールで確認した価値）
- 「NEC」と「日本電気」で部分一致の結果が変わる（NECフィールディング等も拾う）→ 会社ごと分割表示で解決
- JV表記が「＋」「含むJV」でバラバラ → 別カウント＋JVバッジで誠実に表示
- 3年合算なのに年度表示が無かった → R5-R7明記を追加（f8dadc8）
